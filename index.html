Properament
B0

Projecte web

Defineix abans de construir.

Un web no comença escollint un tema. Comença identificant una necessitat real i decidint quin resultat vols oferir.

Avui faràs

  • Escollir un client o context fictici creïble.
  • Definir públic, objectiu i continguts mínims.
  • Escriure criteris d’èxit verificables.

Has de conservar

  • Una fitxa breu del projecte.
  • Un esquema inicial de les pàgines.
  • Una primera llista de tasques de la parella.

Idea clau: cada decisió que prenguis ara t’estalviarà canvis confusos més endavant.

B1

Arquitectura

Entén la cadena abans d’automatitzar-la.

Quan obres un web, el navegador demana una pàgina. El servidor web la processa amb l’aplicació i, si cal, consulta la base de dades.

Navegador→Apache + PHP→WordPress↔MariaDB

Vocabulari essencial

  • Client: el navegador de qui visita.
  • Servidor: qui ofereix el servei.
  • Contenidor: entorn aïllat per executar una aplicació.

Comprova-ho

  • Pots explicar el recorregut d’una petició?
  • Saps per què WordPress necessita MariaDB?
  • Distingeixes una imatge Docker d’un contenidor?
B2

Desplegament

Desplega WordPress sense perdre hores.

La instal·lació es fa a Ubuntu Server 22.04 dins d’IsardVDI. Si treballes des d’una màquina Windows, la faràs servir com a client per connectar-te al servidor.

Abans de començar

  • Tens una VM Ubuntu Server engegada.
  • Pots executar ordres amb sudo.
  • Tens connexió de xarxa i espai de disc.

Seqüència de treball

  1. Instal·la Docker Engine i el connector Compose.
  2. Crea una carpeta de projecte.
  3. Prepara el fitxer compose.yaml.
  4. Inicia els serveis i comprova’n l’estat.
  5. Acaba l’assistent de WordPress al navegador.
docker compose up -d
docker compose ps
docker compose logs -f

Recorda: no copiïs contrasenyes reals a captures ni lliuraments. Farem servir valors d’exemple i variables que puguis substituir.

B3

Arquitectura i selecció

Primer ordena; després escull la base visual.

Concreta el públic, la proposta de valor i els recorreguts principals. Després compara rutes gratuïtes i selecciona una plantilla que encaixi amb les funcions reals del projecte.

Construeix

  • Proposta de valor i mapa del lloc.
  • Comparativa de tres plantilles gratuïtes.
  • Ruta escollida: Astra, Blocksy, Ollie o Kadence.
  • Captura, URL i justificació de la decisió.

Comprova

  • No està marcada com a Pro o Premium.
  • Es pot editar amb Gutenberg.
  • Inclou les pàgines i funcions necessàries.
  • No exigeix pagament ni una prova temporal.

Evidència individual: explica quina part de la plantilla conservaries, quina canviaries i quin risc preveus abans d’importar-la.

B4

Importació i blog

Importa amb seguretat i substitueix la demostració.

Fes el punt de retorn indicat pel professorat, importa la plantilla aprovada i transforma-la amb contingut propi. El blog és una part obligatòria del projecte.

Construeix

  • Punt de retorn abans de la importació.
  • Portada, pàgines clau i menú funcional.
  • Blog amb tres entrades i 2–4 categories.
  • Imatges destacades, extractes i enllaços interns.

Comprova

  • No queda lorem ipsum ni contingut de mostra.
  • Portada i pàgina d’entrades ben assignades.
  • No hi ha menús o pàgines duplicades.
  • Els plugins importats són realment necessaris.

Pregunta de control: el web continua semblant una demostració o ja explica el teu projecte?

B5

Identitat i responsive

Transforma la plantilla en un sistema propi.

Defineix estils globals i adapta capçalera, peu, patrons i crides a l’acció. Després prova el mateix recorregut en mòbil, tauleta i escriptori.

Construeix

  • Paleta i tipografies globals.
  • Capçalera, peu i botons coherents.
  • Patrons reutilitzables personalitzats.
  • Composicions adaptables a cada amplada.

Comprova

  • Sense desplaçament horitzontal accidental.
  • Text llegible i botons fàcils d’utilitzar.
  • Menú operable amb teclat i focus visible.
  • Incidència, correcció i reprova registrades.

Responsive: no és només «fer-ho petit»; és conservar lectura, ordre i interacció en cada pantalla.

B6

Plugins

Instal·la menys i justifica millor.

Parteix d’una necessitat i comprova si WordPress ja la resol. Si cal un plugin, revisa’n l’origen, l’actualització, la compatibilitat, les funcions gratuïtes i les dades que utilitza.

Registra

  • Nom i enllaç oficial.
  • Necessitat que resol.
  • Funcions Free i limitacions Pro.
  • Prova real i decisió final.

Evita

  • Dos plugins per fer la mateixa funció.
  • Plugins abandonats o incompatibles.
  • Serveis externs innecessaris.
  • Extensions inactives que no eliminaràs.

Norma: un plugin no s’avalua perquè estigui instal·lat, sinó perquè resol una necessitat i supera una prova.
